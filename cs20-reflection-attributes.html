Глава 20. Рефлексия и атрибуты: typeof, Type, Activator, метаданные

Как программа читает собственные типы в рантайме, что такое typeof и GetType(), как работают Activator и атрибуты, чем платят за рефлексию и почему на ней держатся DI, сериализация и ORM.

основная глава

Рефлексия — это чтение метаданных сборки во время работы программы. Обычный код вызывает методы напрямую, а рефлексия сначала спрашивает у рантайма: «какие у этого типа свойства? какой у них тип? есть ли у этого свойства атрибут?» — и только потом вызывает что-то по имени.

В книге она уже встречалась: «Equals по умолчанию сравнивает поля через рефлексию» (глава 3), «Activator ищет конструктор в рантайме» (глава 6), «DI и рефлексия видят настоящий тип-аргумент» (глава 6). Здесь — что это за механизм, из чего состоит и когда им пользоваться.

Два входа в метаданные:

Type t1 = typeof(Order);            // тип известен на компиляции
var order = new Order { Id = 1 };
Type t2 = order.GetType();          // тип берётся у объекта

Console.WriteLine(t1 == t2);                    // True — это один и тот же объект Type
Console.WriteLine(t1.Name + " / " + t1.FullName); // Order / Order

Вывод

True
Order / Order

Разница только в источнике: typeof компилятор подставляет сам (работает и без объекта), а GetType() — виртуальный метод object, который возвращает настоящий тип: для объекта, лежащего в переменной базового типа, это будет наследник. И то и другое даёт один и тот же объект System.Type — в рантайме тип существует в единственном экземпляре (reification, глава 6).

Console.WriteLine(string.Join(",", args.Select(a => a.Name)));        // TKey,TValue

Свойства и методы по имени: GetValue / SetValue

Член типа описывается объектами PropertyInfo, MethodInfo, ConstructorInfo. У них можно спросить метаданные и попросить выполнить действие:

var order = new Order { Id = 7, Total = 99.5m };
var prop = typeof(Order).GetProperty("Id")!;

Console.WriteLine(prop.GetValue(order));       // 7  — читаем (обратите внимание: возвращается object)
prop.SetValue(order, 8);                       // пишем
Console.WriteLine(order.Id);                   // 8

Console.WriteLine(prop.PropertyType.Name + " CanWrite=" + prop.CanWrite);   // Int32 CanWrite=True

Вывод

7
8
Int32 CanWrite=True

Что важно знать про этот уровень:

  • GetValue возвращает object — для значимых свойств это упаковка (глава 4), а обратно нужен Convert/приведение.
  • Имя чувствительно к регистру: GetProperty("id") вернёт null, и следующая строка упадёт с NullReferenceException. Именно поэтому библиотеки кэшируют найденные PropertyInfo и проверяют на null явно.
  • По умолчанию — только публичные члены. Приватные доступны через BindingFlags.NonPublic, но это почти всегда признак того, что вы лезете не туда.
  • Ошибка в имени — ошибка в рантайме. Компилятор строку "Id" не проверяет, поэтому рефлексию в горячем коде прячут за nameof и тестами.
Console.WriteLine(typeof(Order).GetProperty("id") is null);   // True — регистр другой

Вывод

True

Activator и «мини-DI»: создать объект по типу

Самый частый сценарий рефлексии — «у меня есть Type, сделай мне экземпляр». Ровно это и делает контейнер зависимостей: находит конструктор, подбирает аргументы по их типам, создаёт объект.

static object? Create(Type type, Func<Type, object?> resolve)
{
    var ctor = type.GetConstructors()
                   .OrderByDescending(c => c.GetParameters().Length)
                   .First();                                   // самый «жадный» конструктор
    var args = ctor.GetParameters()
                   .Select(p => resolve(p.ParameterType))       // по типу параметра ищем зависимость
                   .ToArray();
    return ctor.Invoke(args);
}

var report = Create(typeof(Report),
    t => t == typeof(IClock) ? new SystemClock() : null);

Console.WriteLine(report);      // Report with SystemClock

Вывод

Report with SystemClock

Настоящий DI-контейнер (глава 15 .NET-книги) делает то же самое плюс кэширование, времена жизни (Singleton/Scoped/Transient), проверку циклов и обработку ошибок. А самый простой вариант — Activator.CreateInstance, если конструктор без параметров:

var o = Activator.CreateInstance(typeof(Order));   // object?
var typed = Activator.CreateInstance<Order>();     // Order — без приведения

Ошибки рефлексии приходят в рантайме и часто завёрнутыми: если конструктор бросил исключение, наружу выйдет TargetInvocationException, а настоящее — внутри InnerException.

public sealed class Boom { public Boom() => throw new InvalidOperationException("inside ctor"); }

try { Activator.CreateInstance(typeof(Boom)); }
catch (Exception e)
{
    Console.WriteLine(e.GetType().Name + " / inner: " + e.InnerException?.GetType().Name);
}

Вывод

TargetInvocationException / inner: InvalidOperationException

Запомнить стоит и другой случай: Activator вызывает только публичный конструктор без параметров, иначе — MissingMethodException («No parameterless constructor defined for type 'Hidden'»), даже если приватный конструктор есть.

Атрибуты: данные, которые читает кто-то другой

Атрибут — класс, унаследованный от System.Attribute, которым помечают тип, член или параметр. Сам по себе он ничего не выполняет: это данные в метаданных, а смысл им придаёт тот, кто их читает — компилятор, библиотека или ваш код.

[AttributeUsage(AttributeTargets.Property)]
public sealed class ColumnAttribute : Attribute
{
    public ColumnAttribute(string name) => Name = name;
    public string Name { get; }
}

public sealed class Order
{
    [Column("order_id")] public int Id { get; init; }
    [Column("total")]    public decimal Total { get; init; }
    public string Comment { get; init; } = "";
}

Имя в коде и имя класса различаются: пишут [Column], а класс называется ColumnAttribute — суффикс Attribute компилятор добавляет сам. Чтение — обычная рефлексия:

foreach (var p in typeof(Order).GetProperties())
{
    var col = p.GetCustomAttribute<ColumnAttribute>();
    Console.WriteLine(p.Name + " -> " + (col is null ? "(нет атрибута)" : col.Name));
}

Вывод

Id -> order_id
Total -> total
Comment -> (нет атрибута)

Это уже половина мини-ORM: осталось взять значения свойств и собрать из имён колонок SQL. GetCustomAttribute<T>() возвращает null, если атрибута нет — поэтому он удобнее, чем GetCustomAttributes().First(), который на отсутствии бросит исключение.

Кто читает атрибуты — три разных «читателя», и путать их не стоит:

Кто читаетКогдаПримеры
Компиляторпри сборке[Obsolete], [EnumeratorCancellation] (глава 13), [SetsRequiredMembers] (глава 3)
Библиотека через рефлексиюв рантайме [JsonPropertyName] — System.Text.Json; [Column] — EF Core; [FromQuery] — ASP.NET Core

Пример «читает компилятор» — [Obsolete]: предупреждение появляется на сборке, без всякой рефлексии в рантайме.

[Obsolete("используйте NewApi")]
public static void OldApi() { }

OldApi();      // вызываем — компилятор предупреждает

Вывод компилятора

warning CS0618: 'Demo.OldApi()' is obsolete: 'используйте NewApi'

Сколько стоит рефлексия

Рефлексию часто ругают «за медленность», но цифры зависят от того, что именно делать. Замер на этой машине (net8.0, 1 000 000 итераций, Stopwatch, доступ к одному свойству целого типа):

ОперацияВремяВо сколько раз медленнее прямого доступа
прямое чтение order.Id~5 нс1×
делегат из CreateDelegate~6 нс~1,2×
скомпилированное выражение (Expression.Compile())~6 нс ~1,1×
PropertyInfo.GetValue (кэшированный)~42 нс~9×
GetProperty("Id") + GetValue каждый раз~110 нс ~22×
первый Type.GetType(…) / загрузка метаданных~0,3 мс разово

Вывод не «рефлексия — это 100× медленно», а конкретнее: дорого искать член заново и каждый раз упаковывать результат. Кэшированный PropertyInfo, а тем более делегат или скомпилированное выражение, стоят почти как прямой вызов. Поэтому в библиотеках (DI, сериализаторы, ORM) рефлексия работает один раз — при первом обращении к типу, — а дальше используется кэш.

// ✘ поиск члена на каждое обращение
for (int i = 0; i < 10_000; i++)
    total += (decimal)typeof(Order).GetProperty("Total")!.GetValue(order)!;

// ✔ один раз нашли — дальше только читаем
var prop = typeof(Order).GetProperty("Total")!;
for (int i = 0; i < 10_000; i++)
    total += (decimal)prop.GetValue(order)!;

Ограничения: trimming, AOT и генераторы исходников

У рефлексии есть цена, которую не измеришь секундомером: код, который ищет члены по строкам, нельзя обрезать. При публикации с trimming (обрезка неиспользуемого кода) или в AOT компилятор не видит, что GetProperty("Total") вообще что-то использует, и может выбросить свойство. Программа скомпилируется, а в рантайме получит null из GetProperty или MissingMethodException.

  • Подсказки анализатору: атрибуты [DynamicallyAccessedMembers] и [RequiresUnreferencedCode] говорят, какие члены нужны во время работы.
  • Source generators — современная альтернатива: код генерируется на этапе компиляции, поэтому виден триммеру и работает в AOT. Так устроены System.Text.Json (source-gen режим), LibraryImport, регулярные выражения и EF Core Compiled Models.
  • Правило: рефлексия на старте и в инструментах — нормально; рефлексия в горячем пути публичного API и в AOT-сборке — почти всегда ошибка проектирования.

Где рефлексия уместна, а где нет

УместнаНе уместна
DI-контейнер, сериализатор, ORM — один раз на тип, с кэшем Обработка каждого HTTP-запроса «по имени свойства»
Тесты и моки, где важна гибкость, а не скорость Внутренний цикл обработки данных (там нужен прямой доступ или делегат)
Инструменты: миграции, кодогенерация, анализаторы, консольные утилиты Обход приватных полей «чтобы не менять дизайн» — это скрывает проблему
Плагины: загрузка сборок и поиск реализаций интерфейса Замена обычного полиморфизма: is/switch и интерфейсы почти всегда лучше

Ловушки

  • Имя члена — строка. Опечатка или регистр дают null и NullReferenceException в рантайме. Пишите имена через nameof и покрывайте тестами.
  • GetCustomAttribute<T>() возвращает null, если атрибута нет, — проверяйте. А GetCustomAttributes().First() на пустом списке бросит исключение.
  • Исключения заворачиваются в TargetInvocationException: настоящее — в InnerException. Логируйте вложенное, иначе стек будет указывать на Invoke.
  • Приватные члены (BindingFlags.NonPublic) доступны, но переименование поля при рефакторинге сломает такой код без предупреждения.
  • GetValue упаковывает значимые значения — на большом объёме это заметные аллокации и упаковка (глава 4).
  • Атрибут — не проверка. Пометка [Required] или ваша [Column] ничего не делает, пока кто-то их не прочитает: без читателя это просто комментарий в метаданных.
  • В AOT/trimming поиск по строкам может не найти член вовсе — смотрите раздел выше.
★ Что запомнить из главы
  • Рефлексия — чтение метаданных в рантайме: typeof (тип известен на компиляции), GetType() (настоящий тип объекта).
  • Type — классификация (IsClass/IsValueType), наследование, generic-часть (IsGenericTypeDefinition, GetGenericArguments, MakeGenericType), члены и атрибуты.
  • Члены ищутся по имени (GetProperty("Id"), регистр важен) и вызываются через GetValue/SetValue/Invoke; GetValue возвращает object.
  • Activator/конструктор создают объект по Type — на этом стоит DI; исключения приходят завёрнутыми в TargetInvocationException.
  • Атрибуты — данные; их читает компилятор ([Obsolete] → CS0618), библиотека ([JsonPropertyName]) или ваш код (GetCustomAttribute<T>()).
  • Цена: кэшированный PropertyInfo ~9× медленнее прямого доступа, поиск члена на каждое обращение ~22×, делегат/выражение — почти как прямой вызов. Кэшируйте.
  • Ограничения: рефлексия плохо дружит с trimming/AOT; альтернатива — source generators и генерация кода на этапе компиляции.
