Глава 16. Точка входа и хостинг приложения

Каркас, который связывает всё вместе: где регистрируются сервисы, где берётся конфигурация и в каком порядке приложение запускается.

Program.cs — точка входа

var builder = WebApplication.CreateBuilder(args);

// 1) регистрация сервисов в контейнере (глава 15)
builder.Services.AddScoped<IOrderRepository, OrderRepository>();
builder.Services.AddControllers();

var app = builder.Build();               // 2) собрать приложение

// 3) настроить конвейер обработки запроса (глава 19)
app.UseHttpsRedirection();
app.MapControllers();

app.Run();                               // 4) запустить и слушать

Что такое Generic Host

Строка WebApplication.CreateBuilder(args) создаёт не «настройки», а хост — каркас приложения. «За билдером» стоит Generic Host, и вот что он приносит:

var builder = WebApplication.CreateBuilder(args);
//    ▲ builder — это WebApplicationBuilder; внутри уже создан Host
//      builder.Services      — DI-контейнер (сюда AddScoped/AddSingleton)
//      builder.Configuration — конфигурация
//      builder.Logging       — настройка логов
//      builder.Environment   — Development / Production

var app = builder.Build();
//    ▲ здесь контейнер «застывает»: после Build() новые регистрации не принимаются

app.Run();
//    ▲ запускает хост: поднимает Kestrel, стартует IHostedService,
//      ждёт сигнала остановки и корректно завершает работу

Увидеть это можно в отладке: поставьте точку останова на builder — тип WebApplicationBuilder, у него есть свойство Host. А в минимальном воркере без веба тот же хост создаётся строкой Host.CreateApplicationBuilder().

Важно: это не только веб. Консольное приложение, воркер и даже WPF поднимают тот же Host — поэтому DI и конфигурация работают одинаково везде.

Порядок важен

Сервисы регистрируются до Build() (потом контейнер уже построен). А конвейер (Use…, Map…) настраивается после — уже на собранном приложении.

Окружения

Хост знает текущее окружение (Development, Staging, Production) — переменной ASPNETCORE_ENVIRONMENT / DOTNET_ENVIRONMENT. От него зависит:

  • какой файл настроек подхватится (appsettings.Development.json) — глава 17;
  • включать ли подробные страницы ошибок и валидацию сервисов (глава 15).
if (app.Environment.IsDevelopment())
{
    app.UseDeveloperExceptionPage();
}

Остановка приложения

Хост передаёт CancellationToken, по которому сервисы должны корректно завершиться (graceful shutdown): дописать данные, отпустить соединения. Это важно в контейнерах и при деплое.

Фоновые сервисы: IHostedService и BackgroundService

Хост умеет не только «поднять веб-сервер»: он же запускает и останавливает фоновые сервисы. Это любые классы, зарегистрированные как AddHostedService<T>(). Они запускаются после старта хоста и останавливаются при его остановке.

IHostedServiceBackgroundService
Что этоИнтерфейс из двух методов: StartAsync и StopAsync Базовый класс, который реализует IHostedService за вас и добавляет ExecuteAsync
Когда братьНужен полный контроль над стартом/остановкойОбычный «цикл работы приложения»: читать очередь, обрабатывать пачки
public sealed class ImportWorker(
    IServiceScopeFactory scopes,      // singleton → фабрика scope, а не DbContext (гл. 15)
    ILogger<ImportWorker> log) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)     // токен остановки хоста
        {
            try
            {
                await using var scope = scopes.CreateAsyncScope();          // свой scope на итерацию
                var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();

                await ImportNextBatchAsync(db, stoppingToken);              // отмена дойдёт внутрь
                await Task.Delay(TimeSpan.FromSeconds(1), stoppingToken);   // пауза, прерываемая отменой
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
            {
                break;                                                      // штатная остановка
            }
            catch (Exception ex)
            {
                log.LogError(ex, "итерация импорта упала — продолжаем");     // не роняем хост
            }
        }
    }
}

// регистрация
builder.Services.AddHostedService<ImportWorker>();
  • Жизненный цикл: StartAsync вызывается при старте хоста, ExecuteAsync работает в фоне, StopAsync — при остановке. Асинхронная часть StartAsync завершается сразу после запуска задачи, поэтому «долгая инициализация» в ExecuteAsync не блокирует старт приложения.
  • Токен остановки (stoppingToken) приходит от хоста: в контейнере — по SIGTERM. Пока задача его слушает, остановка происходит быстро; если игнорировать — хост подождёт ShutdownTimeout и убьёт процесс (гл. 28).
  • Исключение из ExecuteAsync по умолчанию останавливает хост (BackgroundServiceExceptionBehavior.StopHost): фоновый сервис не должен падать молча. Поэтому «каждая итерация в своём try/catch», а не «весь цикл в одном».
  • Scope: фоновый сервис — singleton, поэтому scoped-сервисы (DbContext) берутся через IServiceScopeFactory на каждую единицу работы, иначе будет captive dependency (гл. 15, паттерны гл. 4).
  • Не Task.Run в контроллере и не _ = …: работа должна быть зарегистрирована в хосте, чтобы её можно было остановить и увидеть её ошибки (C# гл. 10).
★ Что запомнить

Program.cs — это «сборочный цех»: создать билдер → зарегистрировать сервисы → собрать → настроить конвейер → запустить. Всё остальное (конфигурация, логи, фон, DI) приходит от Generic Host и работает одинаково в веб-, консольных и desktop-приложениях.
