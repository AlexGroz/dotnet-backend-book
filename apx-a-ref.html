Приложение A. ref, out и in: передача по ссылке

Справочное приложение для тех мест, где в основном тексте встречаются ref, out и in — например, Interlocked.Increment(ref counter) в главе 9.

По умолчанию — «по значению»

В C# аргументы метода передаются по значению: метод получает копию. Значит, изменить оригинал он не может.

void PlusOne(int x) { x = x + 1; }   // меняется только копия

int a = 5;
PlusOne(a);
Console.WriteLine(a);   // 5 — оригинал не изменился
Тонкость для ссылочных типов

У ссылочного типа «по значению» передаётся копия ссылки. Значит, поля объекта изменить можно (объект-то тот же), а вот заменить сам объект — нет:

void Rename(User u) { u.Name = "Новое"; }   // изменит объект — ссылка та же
void Replace(User u) { u = new User(); }    // НЕ изменит: заменилась только копия ссылки

ref — передать саму переменную

ref означает «передать по ссылке»: метод получает не копию, а ту же самую переменную и может её изменить.

void PlusOneRef(ref int x) { x = x + 1; }   // меняем оригинал

int b = 5;
PlusOneRef(ref b);
Console.WriteLine(b);   // 6

Именно поэтому сигнатуры выглядят так: Interlocked.Increment(ref int location) — методу нужно изменить исходное значение.

out — вернуть значение наружу

out — тоже «по ссылке», но назначение другое: отдать результат из метода. Внутри метода параметр обязан быть присвоен.

// вернуть и результат, и значение одним вызовом
bool ok = int.TryParse("42", out int value);

if (ok)
{
    Console.WriteLine(value);   // 42
}

// «получить значение из словаря» — тоже через out
if (_cache.TryGetValue(id, out var user))
{
    Use(user);
}

in — по ссылке, но только для чтения

in передаёт по ссылке без права изменения. Смысл — не менять оригинал, а не копировать большие struct. Для маленьких типов (int) смысла нет.

struct BigStruct { public long A, B, C, D, E, F; }

void Read(in BigStruct s)   // копирования нет, изменить нельзя
{
    // s.A = 1;   // ошибка компиляции — только чтение
    Console.WriteLine(s.A);
}

Ещё две формы, которые встретятся
  • ref readonly — вернуть ссылку на данные, но без права записи;
  • ref-возврат из метода (ref int Get(...)) — продвинутая техника для горячих путей (CollectionsMarshal, глава про аллокации).
★ Что запомнить

Обычно — копия. ref — «та же переменная, можно менять». out — «та же переменная, чтобы вернуть результат наружу». in — «та же переменная, но только для чтения» (экономия копирования).
