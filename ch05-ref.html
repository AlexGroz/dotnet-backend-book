Глава 6. ref, out и in: передача по ссылке

Как аргументы попадают в метод: по значению или по ссылке. Это нужно понимать там, где встречаются ref, out и in — например, Interlocked.Increment(ref counter) в главе 10.

По умолчанию — «по значению»

В C# аргументы метода передаются по значению: метод получает копию. Значит, изменить оригинал он не может.

void PlusOne(int x) { x = x + 1; }   // меняется только копия

int a = 5;
PlusOne(a);
Console.WriteLine(a);   // 5 — оригинал не изменился
Тонкость для ссылочных типов

У ссылочного типа «по значению» передаётся копия ссылки. Значит, поля объекта изменить можно (объект-то тот же), а вот заменить сам объект — нет:

void Rename(User u) { u.Name = "Новое"; }   // изменит объект — ссылка та же
void Replace(User u) { u = new User(); }    // НЕ изменит: заменилась только копия ссылки

ref — передать саму переменную

ref означает «передать по ссылке»: метод получает не копию, а ту же самую переменную и может её изменить.

void PlusOneRef(ref int x) { x = x + 1; }   // меняем оригинал

int b = 5;
PlusOneRef(ref b);
Console.WriteLine(b);   // 6

Именно поэтому сигнатуры выглядят так: Interlocked.Increment(ref int location) — методу нужно изменить исходное значение.

out — вернуть значение наружу

out — тоже «по ссылке», но назначение другое: отдать результат из метода. Внутри метода такой параметр обязан получить значение — иначе код не скомпилируется.

// вернуть и «получилось ли», и само значение — одним вызовом
bool ok = int.TryParse("42", out int value);

if (ok)
{
    Console.WriteLine(value);   // 42
}

// «достать значение из словаря» — тоже через out
if (_cache.TryGetValue(id, out var user))
{
    Use(user);
}
Что делают TryParse и TryGetValue

Оба построены на приёме «Try-метод»: он не бросает исключение, а возвращает логическое «получилось / не получилось», а само значение отдаёт через out.

  • int.TryParse("42", out int value) — «попробуй превратить строку в число». Если строка не число, вернёт false и ничего не сломает. Сравните с int.Parse("abc") — он бросит исключение, а это дорого (глава 7).
  • dict.TryGetValue(id, out var user) — «есть ли в словаре такой ключ?». Если есть — true и значение в user; если нет — false. Без исключений и без двух обращений к словарю.

Одна строка вместо «поиск + проверка» — отсюда и популярность out в реальном коде.

in — по ссылке, но только для чтения

in передаёт по ссылке без права изменения. Смысл этого ключевого слова — избежать копирования большого struct: метод получает ссылку на оригинал, но изменить его не может. Для маленьких типов (например, int) выгоды нет: копия стоит столько же, сколько ссылка.

struct BigStruct { public long A, B, C, D, E, F; }

void Read(in BigStruct s)   // копирования нет, изменить нельзя
{
    // s.A = 1;   // ошибка компиляции — только чтение
    Console.WriteLine(s.A);
}

Сравнение

СпособЧто передаётсяМожно менять оригинал?Типичное применение
обычноКопия значенияНет99% кода
refСама переменнаяДаInterlocked, свои методы
outСама переменнаяДа (обязан присвоить)TryParse, TryGetValue
inСама переменная (только чтение)НетБольшие struct, чтобы не копировать
Ещё две формы, которые встретятся
  • ref readonly — вернуть ссылку на данные, но без права записи;
  • ref-возврат из метода (ref int Get(...)) — продвинутая техника для горячих путей (CollectionsMarshal, глава про аллокации).
★ Что запомнить

Обычно — копия. ref — «та же переменная, можно менять». out — «та же переменная, чтобы вернуть результат наружу». in — «та же переменная, но только для чтения» (экономия копирования).
