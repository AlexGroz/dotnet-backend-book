Часть I · Фундамент: язык и память

Глава 1. Как .NET выполняет код: CLR, JIT, типы

Прежде чем говорить о производительности, полезно понять, что вообще происходит с кодом C# — от компиляции до машинных инструкций. Это объясняет стоимость аллокаций, «прогрев» и разницу между типами.

Путь кода: C# → IL → машинный код

  1. Компилятор C# (Roslyn) переводит исходник не в машинный код, а в промежуточный язык IL (Intermediate Language) и метаданные. Результат — сборка .dll.
  2. CLR (Common Language Runtime) загружает сборку и во время выполнения JIT-компилирует методы из IL в машинный код того процессора, на котором работает приложение.
  3. Дальше метод выполняется уже как «родной» машинный код.
Зачем это знать

Из этого факта следуют важные вещи: существует «прогрев» (первые вызовы метода медленнее — его ещё не скомпилировали), а оптимизации применяются не ко всему коду сразу. Поэтому микробенчмарки всегда делают с разогревом (см. главу 14).

Tiered compilation и AOT — кратко

  • Tiered compilation: сначала метод компилируется «быстро и просто», а если он оказался горячим — пересоздаётся с полными оптимизациями. Так старт быстрый, а горячий код — быстрый.
  • ReadyToRun / Native AOT компилируют заранее, чтобы сократить время старта (важно для CLI и лямбд). Для серверных приложений это чаще деталь, а не необходимость.

Управляемый код и память

C# — управляемый язык: памятью в куче распоряжается не вы, а сборщик мусора (Garbage Collector). Это удобно и снижает число утечек, но накладывает цену — работу GC нужно учитывать под нагрузкой (этому посвящена глава 2).

Ссылочные и значимые типы

Ссылочный тип (class)Значимый тип (struct)
Где живётВ куче, переменная хранит ссылкуСодержимое — «прямо в переменной» (часто на стеке или внутри объекта)
ПрисваиваниеКопируется ссылка (тот же объект)Копируется всё значение
По умолчаниюМожет быть nullНе может быть null (кроме Nullable<T>)
СтоимостьАллокация в кучеБез аллокации (если не «упакован»)

Наглядно: ссылочный vs значимый тип

class PointClass { public int X; }   // ссылочный: живёт в куче
struct PointStruct { public int X; }  // значимый: значение копируется

var a = new PointClass { X = 1 };
var b = a;         // b ссылается на ТОТ ЖЕ объект
b.X = 99;          // a.X тоже станет 99

var c = new PointStruct { X = 1 };
var d = c;         // d — независимая копия
d.X = 99;          // c.X останется 1

«Упаковка» (boxing) — первый мостик к памяти

Когда значимый тип нужно воспринять как object, он «упаковывается» в объект в куче — это лишняя аллокация. Подробно разберём в главе 13, но помнить нужно уже сейчас:

int n = 42;
object boxed = n;   // boxing: аллокация в куче
int back = (int)boxed; // распаковка
★ Что запомнить из главы

Код C# компилируется в IL и JIT-компилируется во время выполнения (отсюда «прогрев»). Памятью управляет GC. Ссылочные типы живут в куче и стоят аллокации, значимые — дешевле, но могут «упаковываться» в объект.
