Глава 9. Составные, частичные, покрывающие и функциональные индексы

Это те приёмы, которые реально ускоряют запросы. Каждый — с «когда применять» и примером.

1. Составной индекс (composite)

Индекс по нескольким колонкам. Помогает, когда запрос фильтрует и сортирует по ним вместе.

CREATE INDEX ON orders (status, created_at DESC);

-- подходит запросу:
SELECT id FROM orders
WHERE status = 'NEW'
ORDER BY created_at DESC
LIMIT 50;

Помните правило «слева направо» (глава 8): условие должно быть на первых колонках. Индекс (status, created_at) не поможет запросу только по created_at.

2. Частичный индекс (partial)

Индексируются не все строки, а только подходящие под условие. Индекс получается меньше и быстрее, а его поддерживать дешевле.

-- индексируем только «новые» заказы (их мало, а запрашивают часто)
CREATE INDEX ON orders (created_at DESC)
WHERE status = 'NEW';

Когда применять: горячее подмножество данных — «активные», «не удалённые», «не обработанные». Именно по ним идёт основная работа, а остальное — архив.

3. Покрывающий индекс (covering, INCLUDE)

В индекс добавляют колонки, которых нет в условии, но которые нужны в результате. Тогда запрос обслуживается целиком индексом — это Index Only Scan (глава 14), в таблицу ходить не нужно.

CREATE INDEX ON orders (status) INCLUDE (created_at, total);

-- запросу нужны только status, created_at, total — таблица не читается:
SELECT created_at, total FROM orders WHERE status = 'NEW';

Когда применять: частый запрос возвращает 1–3 колонки, и вы хотите убрать «прыжки» в таблицу.

4. Функциональный индекс (expression)

Индекс не по колонке, а по выражению. Нужен, когда условие содержит функцию — иначе обычный индекс не сработает.

-- запрос: WHERE lower(email) = 'user@example.com'
-- обычный индекс по email НЕ поможет, нужен такой:
CREATE INDEX ON users (lower(email));

Когда применять: поиск без учёта регистра, по части значения, по приведению типа — везде, где над колонкой вызывается функция.

5. Уникальный индекс (UNIQUE)

Обеспечивает уникальность и ускоряет поиск. Бывает и частичным:

-- уникальность только среди «активных» (удалённые могут повторяться)
CREATE UNIQUE INDEX ON users (email) WHERE deleted_at IS NULL;

Каждый индекс — это место на диске и замедление записи (глава 10). Индексы ставят под конкретные запросы, а не «на всякий случай». И обязательно проверяют результатом: план должен реально использовать новый индекс (главы 13–14).

★ Что запомнить

Составной — под фильтр+сортировку (порядок колонок важен). Частичный — когда горячее лишь подмножество. Покрывающий (INCLUDE) — чтобы не ходить в таблицу. Функциональный — когда в условии функция. И всегда проверяем, что индекс действительно используется.
