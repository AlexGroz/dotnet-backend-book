Глава 12. .NET в контейнере: память, CPU и GC

Cgroup-лимиты, HeapHardLimit, Server GC и почему контейнер убивает процесс с кодом 137

основная глава

Глава в работе

План главы:

  • Как рантайм узнаёт про лимиты: cgroup v1/v2, memory.max, cpu.max, Environment.ProcessorCount внутри контейнера.
  • Куча и лимит: HeapHardLimit по умолчанию — 75 % лимита контейнера, DOTNET_GCHeapHardLimit, GCHeapHardLimitPercent.
  • Server GC и число куч: когда «много ядер хоста» превращается в лишнюю память, DOTNET_PROCESSOR_COUNT, --cpus.
  • OOMKilled: код выхода 137, docker inspect, как отличить OOM от docker kill и от падения приложения.
  • Как смотреть реальное потребление: docker stats, dotnet-counters внутри контейнера (глава 21 книги по .NET).
  • Практика: задать лимиты, прогнать нагрузку, найти момент роста и настроить GC.
