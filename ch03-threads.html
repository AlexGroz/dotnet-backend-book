Глава 3. Потоки и пул потоков

Поток — дорогой ресурс. Разберёмся, как .NET их переиспользует, что такое «голодание» пула и как этого избегать.

Почему поток «дорогой»

Каждому потоку нужен стек (порядка мегабайта виртуальной памяти), а переключение между потоками — работа ядра. Создавать поток под каждый входящий запрос — верный способ положить сервер на нагрузке. Поэтому .NET использует пул потоков.

Thread Pool: worker и I/O-потоки

  • Worker threads — выполняют ваш код и продолжения после await.
  • I/O completion threads — обрабатывают завершение асинхронных операций ввода-вывода.

По умолчанию потоков примерно по числу ядер.

Ключевая идея

Пока идёт настоящая асинхронная I/O-операция (запрос в БД, HTTP-вызов, чтение файла), поток не занят — ОС уведомит приложение по завершении. Один поток обслуживает множество ожидающих операций. Это и есть источник высокой пропускной способности.

«Голодание» пула (thread pool starvation)

Если внутри потока пула делать блокирующее ожидание (.Result, .Wait(), Thread.Sleep, синхронный вызов БД), поток занят, но ничего не делает. Когда запросов больше, чем потоков, остальные встают в очередь, а новые потоки пул добавляет медленно (примерно по одному за 500 мс). Результат — задержка в секунды при свободном CPU.

Антипаттерн №1 в серверном коде

// ✘ поток пула застревает в ожидании
var data = GetDataAsync(id).Result;   // или .Wait()

// ✔ блокировки нет — поток освобождается на время I/O
var data2 = await GetDataAsync(id);
Как распознать голодание

Растёт очередь пула и число потоков, а задержка огромная. Ищем блокирующие вызовы. Поднять ThreadPool.SetMinThreads можно лишь как временную меру — это лечение симптома, а не причины.

Синхронизация — кратко

Когда несколько потоков работают с общими данными, нужна синхронизация:

  • lock — простейшая защита участка кода (короткого, без await внутри).
  • SemaphoreSlim — ограничение числа одновременных операций, умеет ждать асинхронно (WaitAsync).
  • Interlocked — атомарные операции над числом (без блокировки).
  • Конкурентные коллекции (ConcurrentDictionary и др.) — потокобезопасные по умолчанию.

Главное правило: не держать блокировку вокруг долгой работы, а тем более вокруг await.

★ Что запомнить из главы
