Глава 13. EXPLAIN и EXPLAIN ANALYZE: читаем план

Мы знаем, что планировщик выбирает план по стоимости (глава 11). Теперь — как этот план прочитать: без этого оптимизация невозможна.

Что такое план

План — это дерево узлов. Каждый узел делает одну операцию: прочитать таблицу, найти строки по индексу, отсортировать, соединить, сгруппировать. Узлы вложены: родитель получает данные от дочерних.

EXPLAIN vs EXPLAIN ANALYZE

  • EXPLAIN — только предполагаемый план (запрос не выполняется).
  • EXPLAIN ANALYZE — выполняет запрос и добавляет фактические метрики. Именно это нужно для оптимизации.
  • BUFFERS — добавить статистику по страницам (из кэша / с диска).
EXPLAIN (ANALYZE, BUFFERS) SELECT ... ;
ВАЖНО

EXPLAIN ANALYZE реально выполняет запрос. Для тяжёлых запросов на продакшене — снимайте план на реплике или в транзакции: BEGIN; EXPLAIN ANALYZE …; ROLLBACK;

Как читать метрики узла

Seq Scan on orders  (cost=0.00..8000.0 rows=5000 width=24)
                    (actual time=0.02..380.9 rows=480000 loops=1)
      ▲ оценка планировщика                     ▲ фактические значения
ЧастьЧто означает
cost=начало..итогоСтоимость «до первой строки» и «до последней» (в условных единицах)
rowsОценка числа строк на выходе узла
widthСредний размер строки в байтах
actual time=старт..итогоФактическое время: до первой строки и до конца
actual rowsФактическое число строк
loopsСколько раз узел выполнялся
Главная формула чтения

Общее время узла ≈ actual time × loops. Узел с маленьким actual time, но большим loops, может «съедать» всё время. И наоборот — не пугайтесь большого actual time у узла с loops = 1, если он «тяжёлый» сам по себе.

Порядок разбора плана

  1. Смотрим Execution Time — сколько выполняется запрос.
  2. Находим узлы с наибольшим total time (actual time × loops) — это «горячие точки».
  3. Сравниваем rows (оценка) и actual rows (факт). Большое расхождение = плохая статистика = неверный план (глава 12).
  4. Смотрим способ доступа к данным (Seq Scan, Index Scan…) — глава 14.
  5. Смотрим, как соединены таблицы (глава 15).

Пример: что здесь не так?

Hash Join  (cost=1120.5..9430.1 rows=50 width=40)
           (actual time=8.311..402.774 rows=50 loops=1)
  -> Seq Scan on orders o  (cost=0.00..8000.0 rows=5000 width=24)
                           (actual time=0.02..380.9 rows=480000 loops=1)
        Filter: (status = 'NEW'::text)
        Rows Removed by Filter: 4520000
→ Оценка: 5 000 строк. Факт: 480 000. Расхождение почти в 100 раз:
  статистика устарела → план неверный → Seq Scan вместо Index Scan.
★ Что запомнить

План — дерево узлов; EXPLAIN ANALYZE показывает факт. Читаем: находим дорогой узел по actual time × loops и сравниваем rows с actual rows. Именно это расхождение — самая частая причина плохих планов. Детальный список полей и «красные флаги» — в главе 17.
