Глава 10. null, ?. и ссылка на самого себя

Три вещи, без которых непонятна половина кода с паттернами: что такое null, как работает ?. и почему класс может содержать поле своего же типа.

основная глава

Что такое null

null — это отсутствие ссылки: переменная есть, а объекта, на который она указывает, нет. У значимых типов (int, DateTime, struct) такого состояния нет — там «пусто» это default (нули).

string? name = null;      // ссылки нет
Console.WriteLine(name.Length);            // ✘ NullReferenceException
Console.WriteLine(name?.Length);           // ✔ null: вызова не было

Nullable reference types (string?, Customer?) — это подсказка компилятору: «здесь может быть null». На работу в рантайме она не влияет, но заставляет обработать случай.

Оператор ?.: вызвать, только если не null

Читается буквально: «если слева не null — вызови/прочитай; иначе верни null».

Check? _next = null;

// это:
var result = _next?.Run(amount);

// означает ровно следующее:
var result2 = _next is null ? null : _next.Run(amount);
ЗаписьЧто делаетТип результата
x?.Method()Вызов, только если x не nullT? (nullable)
x?.PropertyЧтение свойства, только если не nullT?
x?[i]Индексатор, только если не nullT?
x?.A?.BЦепочка: остановится на первом nullT?
x!.Method()«я уверен, что не null» — проверки нетT
Почему в цепочке пишут _next?.Run(...), если тип уже Check?

Тип Check? — это обещание компилятору «тут может быть null». Но чтобы вызвать метод у nullable-ссылки, нужно сначала проверить, что она не null. ?. — это и есть встроенная проверка: «если null — не вызывай». Без него код _next.Run(...) не скомпилируется (предупреждение), а если бы скомпилировался — упал бы.

Родственные операторы

string? name = null;

string a = name ?? "без имени";          // ?? — «если null, взять правое»
name ??= "значение по умолчанию";        // ??= — присвоить, если null

int? count = null;
int n = count ?? 0;                      // 0

// «получить или упасть» — частая идиома в сервисах
var order = await repo.FindAsync(id) ?? throw new NotFoundException(id);

// проверки без операторов
if (order is null) { … }
if (order is not null) { … }

Класс, который ссылается на самого себя

Вопрос из главы про цепочку: «как класс Check может содержать поле своего же типа private Check? _next, если класса ещё нет?» Ответ: потому что поле — это ссылка, а не вложенный объект.

public sealed class Node
{
    public int Value;
    public Node? Next;          // ✔ ссылка на тот же тип — законно
}

var first = new Node { Value = 1 };
first.Next = new Node { Value = 2 };
first.Next.Next = new Node { Value = 3 };

// обход: идём по ссылкам, пока не дойдём до null
for (var node = first; node is not null; node = node.Next)
    Console.WriteLine(node.Value);      // 1, 2, 3
  • Ссылка занимает фиксированный размер (8 байт на 64-битной системе) — компилятору не нужно знать полный размер Node, чтобы объявить поле-ссылку.
  • Тип «завершён» после объявления: внутри тела класса имя Node уже известно.
  • Так устроены связные списки, деревья, графы и цепочки обработчиков.
А со struct так нельзя

struct S { public S Inner; } не скомпилируется: значение хранится внутри значения, и размер получился бы бесконечным. Обходной путь — ссылка (S?), массив или class.

Как это работает в цепочке

Соберём цепочку из двух звеньев и посмотрим, что делает _next?.Run(...):

abstract class Check
{
    private Check? _next;                                  // ссылка на следующее звено
    public Check Next(Check next) { _next = next; return next; }

    public string? Run(int amount)
    {
        var error = Validate(amount);
        if (error is not null) return error;               // 1) нашли проблему — остановились
        return _next?.Run(amount);                         // 2) иначе — спросили следующее звено
    }

    protected abstract string? Validate(int amount);
}

sealed class Positive : Check { protected override string? Validate(int a) => a <= 0 ? "сумма ≤ 0" : null; }
sealed class Limit    : Check { protected override string? Validate(int a) => a > 1000 ? "больше лимита" : null; }

var chain = new Positive();          // первое звено
chain.Next(new Limit());             // прицепили второе

Console.WriteLine(chain.Run(-5));    // «сумма ≤ 0»  ← первое звено остановило
Console.WriteLine(chain.Run(5000));  // «больше лимита» ← первое пропустило, поймало второе
Console.WriteLine(chain.Run(100));   // пусто          ← второе звено последнее: _next == null

Ключ к пониманию — последнее звено: у него _next == null, поэтому _next?.Run(amount) возвращает null. Этот null и означает «все проверки пройдены».

Run(-5):    Positive → «сумма ≤ 0»          (до Limit не дошли)
Run(5000):  Positive → null (ок) → Limit → «больше лимита»
Run(100):   Positive → null (ок) → Limit → null (ок) → _next == null → вернули null
★ Что запомнить из главы
  • null — отсутствие ссылки; у значимых типов его нет, есть default.
  • ?. = «если слева не null — вызови, иначе верни null»; результат всегда nullable.
  • ?? — значение по умолчанию, ??= — присвоить, если null, ?? throw … — «получить или упасть».
  • Класс может содержать поле своего типа, потому что это ссылка фиксированного размера; struct — не может.
  • В цепочке _next?.Run(…) возвращает null на последнем звене — это и есть «дошли до конца».
