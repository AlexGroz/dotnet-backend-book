Глава 10. Другие типы индексов и их цена

B-tree покрывает почти всё, но бывают задачи и для других типов. И у любого индекса есть цена — поговорим и о ней.

Типы индексов в PostgreSQL

ТипДля чегоКогда брать
B-tree (по умолчанию)Равенство, диапазоны, сортировка, префикс95% случаев — начинайте с него
HashТолько равенство (=)Редко: B-tree умеет то же и больше
GIN«Множества» внутри значенияПоиск по jsonb, массивам, полнотекстовый поиск
GiSTСложные типы и «соседство»Геоданные, диапазоны, поиск ближайшего
BRINДиапазоны блоковОгромные таблицы с естественным порядком (например, по дате)

GIN — когда значение «составное»

-- поиск внутри jsonb
CREATE INDEX ON events USING gin (payload);

-- полнотекстовый поиск
CREATE INDEX ON articles USING gin (to_tsvector('russian', body));

Ещё GIN (через расширение pg_trgm) — единственный способ ускорить LIKE '%фрагмент%', который B-tree не тянет (глава 8).

BRIN — «мини-индекс» для огромных таблиц

BRIN хранит не значения строк, а краткие диапазоны по блокам страниц. Занимает копейки, но полезен, только если данные физически упорядочены (типично — таблица, куда пишут «по времени», например журнал событий).

Цена индексов

Индекс ускоряет чтение, но у него есть четыре «счёта к оплате»:

Что стоитПочему
Место на диске и в памятиИндекс хранится отдельно и тоже кэшируется; иногда он сравним по размеру с таблицей
Скорость записиКаждый INSERT/UPDATE/DELETE обновляет все индексы таблицы
ОбслуживаниеИндексы «раздуваются» вместе с таблицей и требуют VACUUM / REINDEX (глава 23)
Время планированияЧем больше индексов, тем дольше планировщик перебирает варианты (глава 11)
Правило разумного минимума

Индекс должен отрабатывать конкретные запросы. Индекс «на всякий случай» только замедляет запись и ест место. Если индекс давно никто не использовал — его стоит удалить.

Как найти неиспользуемые индексы

SELECT indexrelname, idx_scan
FROM   pg_stat_user_indexes
WHERE  idx_scan = 0          -- ни разу не использовался
ORDER  BY pg_relation_size(indexrelid) DESC;

Осторожно: «0 использований» может значить и «статистика недавно сброшена». Удаляйте только то, в чём уверены.

Как проверить размер индексов 
SELECT indexrelname,
       pg_size_pretty(pg_relation_size(indexrelid)) AS size
FROM   pg_stat_user_indexes
ORDER  BY pg_relation_size(indexrelid) DESC
LIMIT  10;
★ Что запомнить

Начинайте с B-tree — его хватает почти всегда. Другие типы берите под задачу: GIN — для jsonb/массивов/полнотекста, GiST — для гео и диапазонов, BRIN — для огромных «по времени» таблиц. И помните про цену: место, замедление записи, обслуживание. Индексов должно быть ровно столько, сколько нужно.
