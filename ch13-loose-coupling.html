Глава 13. Слабая связанность: зачем внедрять зависимости

Начинаем часть про сборку приложения. Прежде чем говорить о контейнере зависимостей (глава 14), ответим на вопрос «зачем вообще всё это нужно».

Жёсткая связь — это проблема

Класс, который сам создаёт свои зависимости, «прибит» к конкретным реализациям:

// ✘ OrderService жёстко связан с SqlRepository и строкой подключения
public class OrderService
{
    private readonly SqlRepository _repo = new("Host=db;...");

    public Order Get(int id) => _repo.Find(id);
}

Что здесь плохо:

  • нельзя подставить другую реализацию (кэш, тестовый двойник);
  • нельзя протестировать OrderService без настоящей базы;
  • изменения (другая БД, другой способ хранения) задевают этот класс;
  • строка подключения «зашита» внутрь логики.

Интерфейс как контракт

Решение — зависеть от абстракции (интерфейса), а не от конкретного класса:

public interface IOrderRepository
{
    Order? Find(int id);
}

// ✔ класс зависит от контракта и получает его извне
public class OrderService(IOrderRepository repo)
{
    public Order? Get(int id) => repo.Find(id);
}

Теперь OrderService не знает, откуда приходят данные: база, кэш или заглушка в тесте. Это и есть слабая связанность.

Что это даёт на практике

ВыгодаЧто это значит в работе
ТестируемостьВ тестах подставляем поддельный IOrderRepository вместо БД
ЗаменяемостьМеняем реализацию (БД → кэш → внешний API), не трогая потребителя
Изоляция измененийПравки в одной части системы не расползаются по коду
Параллельная работаКоманды договариваются об интерфейсах и работают независимо
Теперь зависимости нужно «собирать»

Как только класс перестал создавать зависимости сам, кто-то должен их ему передать. Раньше это делали вручную или через статику — и это превращалось в кашу. Поэтому нужен контейнер, который сам собирает объекты и раздаёт зависимости. О нём — глава 14.

★ Что запомнить

Жёсткая связь (класс сам делает new своих зависимостей) мешает тестам и изменениям. Слабая связь — это «зависеть от интерфейса, зависимость получать извне». Именно это и обслуживает внедрение зависимостей в .NET Core.
