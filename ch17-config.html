Глава 17. Конфигурация и опции

Настройки приложения: откуда они берутся, как их читать и почему у «опций» тоже есть жизненные циклы.

Откуда берётся конфигурация

Хост собирает IConfiguration из нескольких источников. Источники применяются по порядку, и последний перекрывает предыдущие:

  1. appsettings.json — базовые значения;
  2. appsettings.{Environment}.json — переопределения для окружения (глава 16);
  3. переменные окружения — то, что задаётся в контейнере/на сервере;
  4. аргументы командной строки;
  5. секреты разработчика (локально) — dotnet user-secrets.
Секреты — не в файле в репозитории

Пароли и ключи не хранят в appsettings.json. Локально — user-secrets, в проде — переменные окружения или менеджер секретов.

Опции: привязка конфигурации к классу

Читать строки конфигурации по всему коду — плохо. Значения привязывают к классу и инжектят его через DI:

public sealed class OrderOptions
{
    public int    PageSize  { get; init; } = 50;
    public string ConnectionString { get; init; } = "";
}

builder.Services
    .AddOptions<OrderOptions>()
    .Bind(builder.Configuration.GetSection("Orders"))
    .ValidateDataAnnotations()   // проверка значений
    .ValidateOnStart();          // падать на старте, а не в рантайме

Три варианта чтения опций (и их lifetimes!)

Здесь мы возвращаемся к жизненным циклам из главы 15 — у опций они тоже есть:

ТипLifetimeКогда брать
IOptions<T>SingletonЗначения не меняются на ходу (обычный случай)
IOptionsSnapshot<T>ScopedНужно перечитывать значения на каждый запрос
IOptionsMonitor<T>SingletonНужны уведомления об изменении настроек
Типичная ошибка

Уверенно сказать «конфигурацию читаю через IConfiguration везде» — устаревший подход. Правильно: один раз привязать к классу и инжектить IOptions<T>. Так настройки валидируются, типизированы и не разбросаны по коду.

public class OrderService(IOptions<OrderOptions> options)
{
    private readonly OrderOptions _opt = options.Value;
    public int PageSize => _opt.PageSize;
}
★ Что запомнить

Конфигурация собирается из нескольких источников (последний побеждает), секреты — не в репозитории. Значения привязываем к классу и получаем через IOptions<T> / IOptionsSnapshot<T> / IOptionsMonitor<T>, помня про их lifetimes и валидацию на старте.
