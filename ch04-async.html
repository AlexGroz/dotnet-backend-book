Глава 4. Асинхронность: async/await и Task

Главный инструмент серверной разработки на .NET: как с малым числом потоков обслуживать много запросов и не превратить это в «стоп-кран».

Суть: I/O-bound против CPU-bound

  • I/O-bound — операция ждёт внешний ресурс (БД, сеть, диск). Ждать нужно асинхронно — поток при этом свободен. Это 90% серверного кода.
  • CPU-bound — операция считает. Здесь помогает параллелизм, но с осторожностью.

Как работает async/await

Компилятор превращает метод с async в машину состояний. В точке await метод не блокирует поток, а сохраняет своё состояние и возвращает управление вызывающему. Когда операция завершится, продолжение выполнится (возможно, на другом потоке).

public async Task<UserDto> GetUserAsync(int id, CancellationToken ct)
{
    var user = await _repo.GetByIdAsync(id, ct); // поток освобождается здесь
    return user;                                  // продолжение после завершения I/O
}

Правило №1: async до конца

Если метод асинхронный — он должен быть таким на всём пути, от эндпоинта до последнего слоя. Смешивание async и синхронного ожидания — главная ошибка новичков и причина «голодания» пула (глава 3).

Что полезно знать

ТемаКоротко
async voidТолько для UI-событий. В сервере — нет: исключения не поймать.
Task.RunНе нужен «чтобы было асинхронно» на сервере — это лишняя работа.
ConfigureAwait(false)В библиотеках — чтобы не возвращаться в исходный контекст. В ASP.NET Core контекста нет, поэтому там менее критично.
ValueTaskЭкономит аллокацию, когда результат часто готов сразу (кэш). Обычно хватает Task.

Параллелизм — но контролируемый

Независимые вызовы — параллельно

// ✘ последовательно: 2 × 100 мс = 200 мс
var a = await GetAAsync(ct);
var b = await GetBAsync(ct);

// ✔ параллельно: ~100 мс
var ta = GetAAsync(ct);
var tb = GetBAsync(ct);
await Task.WhenAll(ta, tb);
Обязательно ограничивайте веер

Неограниченный Task.WhenAll на тысячи элементов исчерпает пул соединений к БД и обрушит задержки. Ограничивайте степень параллелизма:

private static readonly SemaphoreSlim Gate = new(8); // не более 8 сразу

await Gate.WaitAsync(ct);
try   { await ProcessOneAsync(id, ct); }
finally { Gate.Release(); }

Потоковая обработка — IAsyncEnumerable

Для больших результатов отдавайте данные потоком, а не грузите всё в память:

public async IAsyncEnumerable<OrderDto> StreamAsync(
    [EnumeratorCancellation] CancellationToken ct)
{
    await foreach (var o in _db.Orders.AsNoTracking()
                       .Select(x => new OrderDto(x.Id, x.Total))
                       .AsAsyncEnumerable()
                       .WithCancellation(ct))
    {
        yield return o;
    }
}
★ Что запомнить из главы

Async/await позволяет не занимать поток во время I/O — это основа высокой пропускной способности. Правило «async до конца» + ограничение параллелизма закрывают большинство проблем производительности.
