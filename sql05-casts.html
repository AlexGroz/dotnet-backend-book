Глава 5. Приведение типов: CAST и ::

'2026-01-01'::date, count(*)::int, data->>'age'::int — двоеточие с двоеточием встречается в каждом втором примере. Разберём, что оно делает, где применяется и когда из-за него перестаёт работать индекс.

подводящая глава

Что делает ::

:: — это оператор приведения типа (type cast): «возьми значение слева и преобразуй его к типу справа». Полная форма — CAST(выражение AS тип), короткая — выражение::тип. Это одно и то же:

SELECT CAST('2026-01-01' AS date);   -- полная форма
SELECT '2026-01-01'::date;           -- короткая форма, то же самое

-- проверка: оба вернут одинаковый тип
SELECT pg_typeof(CAST('2026-01-01' AS date)),
       pg_typeof('2026-01-01'::date);        -- date | date

Зачем вообще нужно: PostgreSQL строго относится к типам. '2026-01-01' — это строка неизвестного типа, и чтобы сравнивать её с колонкой date, вычитать из неё дни или сортировать как дату, типы надо согласовать явно.

Синтаксис: три вещи, которые надо знать

  • Тип с параметрами. После :: можно писать numeric(18,2), varchar(50), timestamptz, interval — всё, что допустимо в CREATE TABLE: round(avg(total)::numeric, 2).
  • Массивы и цепочки. ::int[] — массив, '{"a":1}'::jsonb — jsonb. Приведения можно соединять: data->>'age'::int — сначала ::int, потом уже результат используется (осторожно с приоритетом, см. ниже).
  • Приоритет. :: «прилипает» к ближайшему выражению очень крепко: -1::int — это -(1::int), а не (-1)::int. Если сомневаетесь — ставьте скобки: (x + y)::numeric.
-- разница видна на делении: 7/2 в целых числах = 3, а не 3.5
SELECT 7 / 2;                   -- 3        (целочисленное деление)
SELECT 7 / 2::numeric;          -- 3.5      (числитель стал numeric)
SELECT 7::numeric / 2;          -- 3.5
SELECT round(7 / 2::numeric, 2);-- 3.50

-- приоритет: :: связывает крепче арифметики
SELECT 2 + 3::text;             -- '23'? нет: здесь будет ошибка типа text + integer
SELECT (2 + 3)::text;           -- '5'

Главная ловушка: приведение над колонкой убивает индекс

Индекс строится по колонке. Если в условии колонка спрятана внутри выражения (created_at::text, date(created_at)), индекс по created_at перестаёт подходить: сервер должен вычислить выражение для каждой строки.

-- ✘ приведение над колонкой: обычный индекс не используется
SELECT * FROM orders WHERE created_at::text LIKE '2026-01%';

-- EXPLAIN покажет:
--   Seq Scan on orders
--     Filter: ((created_at)::text ~~ '2026-01%'::text)     ← функция над колонкой

-- ✔ сравнение колонки с границами того же типа: btree-индекс работает
SELECT * FROM orders
WHERE  created_at >= '2026-01-01' AND created_at < '2026-02-01';
  • Почему так. Индекс хранит значения created_at (timestamptz), а запрос спрашивает про текстовое представление — это другое множество значений, и порядок индекса к нему не применим.
  • Тот же эффект у WHERE date(created_at) = '2026-01-01', WHERE id::text = '42', WHERE to_char(created_at,'YYYY') = '2026'.
  • Что делать: переписать диапазоном (лучший вариант) или построить функциональный индекс по тому же выражению: CREATE INDEX ON orders ((created_at::date));
  • С секциями это важнее вдвойне: диапазон по дате позволяет отбросить целые секции (pruning), а ::text LIKE заставит читать все (глава 26).

Неявные приведения: что сервер делает сам

Явный :: — не единственный путь. Литерал неизвестного типа сервер приводит к типу колонки сам:

-- литерал неизвестного типа приводится к timestamptz: индекс работает
SELECT * FROM orders WHERE created_at >= '2026-01-01';

-- а здесь к тексту приводится КОЛОНКА → индекс уже не применим
SELECT * FROM orders WHERE created_at::text >= '2026-01-01';

Правило: приведение слева (над колонкой) — почти всегда плохо, приведение справа (над литералом или параметром) — нормально.

★ Что запомнить
  • :: = CAST(... AS ...): меняет тип значения, а не формат вывода.
  • Приоритет высокий: сомневаетесь — ставьте скобки.
  • Частые места: литералы, деление, агрегаты, JSON (->> даёт text), даты, склейка, enum, массивы, USING в DDL, параметры в PL/pgSQL.
  • Приведение над колонкой в WHERE отключает обычный индекс → переписывайте диапазоном или стройте функциональный индекс.
  • Приведение литерала или параметра к типу колонки — нормально и индексу не мешает.
