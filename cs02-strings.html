Глава 2. Строки: неизменяемость, пул строк и StringBuilder

Самое частое заблуждение: «string лежит в стеке, поэтому он быстрый». Разберём, где на самом деле живёт строка (карта памяти — глава 1), что такое пул строк, как читать new string('А', 7) и $"{a} {b}" — и когда действительно нужен StringBuilder.

подводящая глава

Строка — ссылочный тип

string (он же System.String) — это класс, а не структура. Значит, объект строки всегда живёт в куче. В стеке (если переменная локальная) лежит только ссылка на этот объект — четыре или восемь байт адреса.

var name = "Алексей";

// что реально произошло:
// 1) в куче существует объект-строка "Алексей";
// 2) в переменной name (на стеке) лежит ССЫЛКА на него.

Console.WriteLine(name.Length);   // 7 — вызываем метод у объекта в куче
Разбираем путаницу

«String лежит в стеке, поэтому он быстрее StringBuilder» — здесь два неверных шага. Во-первых, строка не в стеке: в стеке ссылка. Во-вторых, StringBuilder медленнее на одном изменении (это объект, буфер, метод), но быстрее на сотнях изменений подряд, потому что меняет свой буфер, а не создаёт новую строку.

Почему строка неизменяема

Объект строки после создания нельзя изменить. Любая «модификация» возвращает новую строку, а старая остаётся в куче до сборки мусора.

string a = "abc";
string b = a.ToUpper();     // НЕ меняет a: создаётся новый объект "ABC"

Console.WriteLine(a);       // abc — исходная строка цела
Console.WriteLine(ReferenceEquals(a, b));   // false — это два разных объекта

Неизменяемость — не недостаток, а основа безопасности: строку можно передавать между потоками, использовать как ключ словаря и не бояться, что кто-то её «поправит». Цена — новые объекты при каждой операции.

// ✘ 1000 раз создаём новую строку: 1 + 2 + … + 1000 копий символов
string s = "";
for (int i = 0; i < 1000; i++)
    s += i + ",";

// ✔ один буфер, который меняется на месте
var sb = new StringBuilder(4096);
for (int i = 0; i < 1000; i++)
    sb.Append(i).Append(',');
string result = sb.ToString();     // одна итоговая строка
Сколько это стоит

Конкатенация в цикле — это O(n²) по скопированным символам: на каждой итерации создаётся строка длиннее предыдущей и копируется целиком. StringBuilder держит один массив и дописывает в конец — O(n). Разница на 10 000 итераций — секунды против миллисекунд и мегабайты мусора.

Литералы и интернирование

Строковые литералы (то, что записано в коде в кавычках) хранятся в метаданных сборки, а при загрузке попадают в специальную таблицу — пул интернированных строк (string intern pool). Поэтому два одинаковых литерала — это один и тот же объект:

string a = "Алексей";                        // литерал → уже лежит в пуле
string b = string.Concat("Алек", "сей");     // собрано в рантайме → НОВЫЙ объект
Console.WriteLine(ReferenceEquals(a, b));    // False — объекты разные, хотя Equals = True

string c = string.Intern(b);                 // «положить в пул»: вернётся объект ИЗ пула
Console.WriteLine(ReferenceEquals(a, c));    // True  — это тот же объект, что a
Console.WriteLine(ReferenceEquals(b, c));    // False — сам b остался своим объектом

string other = new string('А', 7);           // "ААААААА" — ДРУГОЕ содержимое
string interned = string.Intern(other);      // интернирует именно "ААААААА"
Console.WriteLine(ReferenceEquals(a, interned)); // False — строки разные
Правило, которое снимает путаницу

ReferenceEquals сравнивает адреса объектов. Два литерала с одинаковым текстом — один объект, поэтому true. Но string.Intern не делает разные строки одной: он лишь возвращает ссылку на объект из пула, если в пуле уже есть строка с тем же содержимым. Поэтому:

  • "Алексей" и "ААААААА" — разное содержимое → ReferenceEquals всегда false, сколько ни интернируй;
  • одинаковое содержимое + обе строки интернированы → true;
  • Intern(b) не превращает b в интернированную строку — b остаётся своим объектом, а пул хранит свою копию.
  • Литерал бесплатен по аллокации при обращении: объект уже создан один раз.
  • Строка из рантайма (конкатенация, Substring, ToString) — всегда новая аллокация в куче.
  • string.Intern экономит память при множестве одинаковых строк, но удерживает их до конца жизни процесса: злоупотребление — это утечка.
Где лежит пул строк

Пул — это таблица ссылок внутри рантайма, а не отдельная область памяти. Сами объекты строк лежат в обычной управляемой куче, а пул держит на них ссылки — поэтому сборщик мусора их не удаляет. Подробнее с картинкой — глава 1.

Что означает new string('А', 7)

Это конструктор String(Char, Int32): «сделай строку из символа 'А', повторённого 7 раз». Второе число — количество повторений, а не индекс и не длина в байтах.

string c = new string('А', 7);        // "ААААААА" — 7 символов
Console.WriteLine(c.Length);          // 7

// другие конструкторы, которые встречаются на практике
new string(new[] { 'h', 'i' });       // "hi" — из массива символов
new string('*', 20);                  // "********************" — разделитель в логе
string.Create(5, 0, (span, _) => span.Fill('x'));   // "xxxxx" — без промежуточных строк

Результат такого конструктора — новая строка в куче, и она не попадает в пул автоматически (в отличие от литерала). Поэтому ReferenceEquals с литералом даёт false.

Как читать $"{a} {b}"

Знак $ перед кавычками включает интерполяцию: внутри строки можно писать выражения в фигурных скобках, и они подставятся в текст.

int count = 3;
string name = "Алексей";

string s1 = $"{name}: {count} заказа";          // "Алексей: 3 заказа"
string s2 = $"Итого: {count * 100:N0} ₽";       // "Итого: 300 ₽" (формат N0 — без копеек)
string s3 = $"{name,10}|";                      // выравнивание по ширине 10
string s4 = $"{DateTime.UtcNow:yyyy-MM-dd}";    // формат даты после двоеточия
  • {выражение} — подставить значение (можно любое выражение, не только переменную);
  • {значение,ширина} — выровнять по ширине (плюс — вправо, минус — влево);
  • {значение:формат} — применить формат: N0, yyyy-MM-dd, F2;
  • {{ и }} — чтобы вывести сами фигурные скобки.

Раньше компилятор превращал такую строку в string.Format с промежуточными объектами. Начиная с C# 10 используется интерполяционный обработчик строк, и во многих случаях результат собирается без лишних промежуточных строк.

Когда StringBuilder не нужен

Он создаёт объект и держит буфер. Если частей две-три — конкатенация или интерполяция проще и не медленнее. Правило: StringBuilder — когда число операций заранее неизвестно или велико.

Сравнение строк: не всё равно, как сравнивать

// ✘ новая строка на КАЖДОЕ сравнение + зависимость от культуры
if (email.ToLower() == "admin@example.com") { }

// ✔ без аллокации и с явным правилом сравнения
if (string.Equals(email, "admin@example.com", StringComparison.OrdinalIgnoreCase)) { }

// ✔ для технических строк (URL, ключи) — Ordinal
if (path.StartsWith("/api/", StringComparison.Ordinal)) { }
  • == для строк сравнивает содержимое, а не ссылки; проверить ссылки — ReferenceEquals.
  • ToLower() ради сравнения — лишняя строка в куче.
  • Ordinal/OrdinalIgnoreCase — для технических строк; культурные сравнения — только для пользовательского текста и сортировки.
Почему «строка на каждое сравнение» — и как это выглядит

ToLower() ничего не меняет на месте (строка неизменяема): он создаёт новый объект в куче. В цикле по 10 000 адресов получится 10 000 временных строк — и все они станут мусором.

email = "Admin@Example.com"
   │
   ├─ ToLower()  →  в куче создан НОВЫЙ объект "admin@example.com"
   ├─ сравнение с литералом → true
   └─ временная строка больше не нужна → мусор для GC

string.Equals(email, "admin@example.com", StringComparison.OrdinalIgnoreCase)
   └─ сравнение «на месте»: новых строк нет, регистр учитывается в момент сравнения

Второй нюанс: ToLower() без аргумента зависит от текущей культуры, поэтому на разных машинах результат может отличаться (классический пример — турецкая «i»). OrdinalIgnoreCase сравнивает предсказуемо и быстрее.

Строка без копий: Span

Substring создаёт новую строку. Если часть нужно только прочитать — берут «окно» без аллокации (подробнее — глава 7 .NET-раздела):

string line = "10,20,30";

string part = line.Substring(0, 2);             // новая строка
ReadOnlySpan<char> window = line.AsSpan(0, 2);   // окно, без аллокации

int value = int.Parse(window);                   // парсинг прямо из окна
Как «окно» может ничего не хранить?

Span<T> — это маленькая структура из двух чисел: ссылка на начало данных и длина. Символы она не копирует — они остаются в исходной строке.

line: "10,20,30"    (объект строки в куче)
       ▲
       │ window = line.AsSpan(0, 2)
       │
       └── ┌───────────────────────┐
           │ ссылка на начало: 0   │  ← сам Span лежит на стеке,
           │ длина: 2              │     это 16 байт
           └───────────────────────┘
      новых символов в куче НЕ появилось

Отсюда и ограничения: Span живёт только на стеке — его нельзя положить в поле класса или «пережить» им await, иначе окно осталось бы, когда данных уже нет. Подробно и с примерами — глава 5.

★ Что запомнить из главы
  • string — ссылочный тип: объект в куче, в переменной — ссылка. «Строка в стеке» — неверно.
  • Строка неизменяема: каждая «модификация» создаёт новую; в цикле это лавина мусора.
  • StringBuilder быстрее не из-за стека, а потому что меняет свой буфер: O(n) вместо O(n²).
  • Литералы интернированы: одинаковые литералы — один объект; строки из рантайма — новые аллокации.
  • Сравнивайте через string.Equals/StringComparison — без временных строк.
