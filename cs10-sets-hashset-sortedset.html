Глава 10. Множества: HashSet и SortedSet

Полный API множеств: Add/Remove/Contains, операции над множествами (UnionWith, IntersectWith, ExceptWith, SymmetricExceptWith), отношения (IsSubsetOf, Overlaps), компаратор, ёмкость, порядок и версия с сортировкой — SortedSet<T>.

основная глава

HashSet<T> — это Dictionary, у которого выкинули значения и оставили ключи. Отсюда всё остальное: хеш-таблица внутри, добавление и поиск за ~O(1), никакого порядка и та же ловушка с изменяемым элементом (глава 9). Сортированная версия — отдельный тип SortedSet<T> на красно-чёрном дереве: O(log n) и всегда по порядку.

Множество нужно там, где вопрос звучит «есть ли это у нас?», а не «что лежит под номером 3»: дедупликация, «уже видели этот id», пересечение прав, разница двух выборок.

Базовый API: Add, Remove, Contains

Главное отличие от списка: Add и Remove возвращают bool — изменилось ли множество. Никаких исключений на повтор и на отсутствие элемента здесь нет.

var set = new HashSet<int> { 1, 2, 3 };

Console.WriteLine(set.Add(4) + " " + set.Add(4));      // True False — второй раз уже есть
Console.WriteLine(set.Remove(2) + " " + set.Remove(42)); // True False — 42 и не было
Console.WriteLine(set.Contains(3) + " " + set.Count);   // True 3

Console.WriteLine(set.RemoveWhere(x => x > 2));        // 2 — сколько удалили
Console.WriteLine(set.Count);                          // 1
set.Clear();
Console.WriteLine(set.Count);                          // 0

Трюк: TryGetValue у множества

Contains отвечает «да/нет», но иногда нужен сам хранимый экземпляр — например, чтобы вернуть канонический объект из кэша. Тогда TryGetValue(probe, out var stored) отдаёт элемент, который лежит в множестве, и ReferenceEquals подтверждает, что это он:

public sealed class Item                                   // равенство по Id (глава 3)
{
    public int Id { get; init; }
    public override bool Equals(object? o) => o is Item i && i.Id == Id;
    public override int GetHashCode() => Id;
}

var users = new HashSet<Item> { new Item { Id = 1 } };
var probe = new Item { Id = 1 };                      // новый объект, равен только по Id

users.Contains(probe);                                // True — равенство по значению
users.TryGetValue(probe, out var stored);             // stored — тот самый объект из множества
Console.WriteLine(ReferenceEquals(stored, users.First()));   // True

Операции над множествами: объединение, пересечение, разность

Все четыре операции меняют само множество (в отличие от LINQ Union/ Intersect, которые возвращают новую последовательность) и ничего не возвращают.

var a = new HashSet<int> { 1, 2, 3, 4 };
var b = new HashSet<int> { 3, 4, 5 };

var c = new HashSet<int>(a); c.UnionWith(b);            // A ∪ B
Console.WriteLine(string.Join(",", c.OrderBy(x => x))); // 1,2,3,4,5

c = new HashSet<int>(a); c.IntersectWith(b);            // A ∩ B
Console.WriteLine(string.Join(",", c.OrderBy(x => x))); // 3,4

c = new HashSet<int>(a); c.ExceptWith(b);               // A ∖ B
Console.WriteLine(string.Join(",", c.OrderBy(x => x))); // 1,2

c = new HashSet<int>(a); c.SymmetricExceptWith(b);      // A Δ B — всё, кроме общего
Console.WriteLine(string.Join(",", c.OrderBy(x => x))); // 1,2,5

Осторожно: операции мутируют получателя

a.UnionWith(b) меняет a, а не возвращает новое множество. Нужен исходный набор — сначала скопируйте: var c = new HashSet<int>(a); c.UnionWith(b);. Второй вариант — LINQ: a.Union(b) возвращает новую последовательность и ничего не портит.

Отношения: подмножество, надмножество, пересечение

Эти шесть методов ничего не меняют — они отвечают, как соотносятся два множества:

var a = new HashSet<int> { 1, 2, 3, 4 };

Console.WriteLine(new HashSet<int> { 2, 1 }.SetEquals(new HashSet<int> { 1, 2 })); // True
Console.WriteLine(new HashSet<int> { 1, 2 }.IsSubsetOf(a));            // True  ⊆
Console.WriteLine(new HashSet<int> { 1, 2 }.IsProperSubsetOf(a));      // True  ⊂ (строго меньше)
Console.WriteLine(a.IsSupersetOf(new HashSet<int> { 1, 2 }));          // True  ⊇
Console.WriteLine(a.IsProperSupersetOf(a));                            // False — равные не «строго»
Console.WriteLine(a.Overlaps(new HashSet<int> { 4, 9 }));              // True  есть общий элемент

Ёмкость, память и компаратор

Как и у словаря, у множества есть внутренние корзины: их можно заказать заранее и ужать после заполнения.

var set = new HashSet<int>();
set.EnsureCapacity(100);       // корзины под 100 элементов — без промежуточных расширений
set.Add(1);
set.TrimExcess();              // ужать под фактический размер

var array = new int[5];
set.CopyTo(array);             // копирование в массив
Console.WriteLine(array[0] + " " + set.Comparer.GetType().Name);

Вывод

1 GenericEqualityComparer`1

Компаратор задаётся в конструкторе и решает, какие элементы считать одинаковыми:

var names = new HashSet<string>(StringComparer.OrdinalIgnoreCase) { "Аня" };

Console.WriteLine(names.Contains("АНЯ"));                          // True
Console.WriteLine(new HashSet<string> { "Аня" }.Contains("АНЯ"));   // False

Вывод

True
False

Правила те же, что в главе 9: Ordinal для идентификаторов и тестов, OrdinalIgnoreCase — когда регистр не должен различать. Компаратор влияет не только на Contains, но и на Remove, и на операции над множествами — они работают по тем же правилам равенства.

Порядок перебора и SortedSet<T>

HashSet порядок не хранит: элементы перебираются в порядке корзин, и полагаться на это нельзя (как и с Dictionary, глава 9). Если порядок нужен как часть контракта — берут SortedSet<T>. Он умеет всё то же плюс доступ к краям и диапазонам:

var sorted = new SortedSet<int> { 5, 1, 3 };

Console.WriteLine(string.Join(",", sorted));            // 1,3,5 — всегда по возрастанию
Console.WriteLine(sorted.Min + " " + sorted.Max);       // 1 5
Console.WriteLine(string.Join(",", sorted.Reverse()));  // 5,3,1
Console.WriteLine(string.Join(",", sorted.GetViewBetween(2, 4)));   // 3 — только из диапазона

var view = sorted.GetViewBetween(1, 3);      // это ЖИВОЕ представление, а не копия
sorted.Add(2);
Console.WriteLine(string.Join(",", view));   // 1,2,3 — новый элемент виден во view

Для SortedSet без компаратора тип обязан реализовывать IComparable<T> — иначе конструктор бросит исключение. Свой порядок задаётся так же, как в главе 8: new SortedSet<Order>(Comparer<Order>.Create((x, y) => y.Total.CompareTo(x.Total))).

Сколько это стоит: List.Contains против HashSet.Contains

Смысл множества виден на поиске. Замер на этой машине: список из 100 000 чисел против множества из тех же чисел, по 2000 проверок «есть ли элемент» (элемент заведомо есть, то есть список каждый раз проходит почти до конца).

var big = Enumerable.Range(0, 100_000).ToList();
var bigSet = big.ToHashSet();

foreach (var x in Enumerable.Range(0, 2000)) big.Contains(99_999 - x);      // O(n) на проверку
foreach (var x in Enumerable.Range(0, 2000)) bigSet.Contains(99_999 - x);   // ~O(1)

Вывод (net8.0)

List.Contains x2000:    24.90 ms
HashSet.Contains x2000:  0.08 ms

Разница ~300×, и она растёт вместе с размером коллекции: у списка каждая проверка — проход, у множества — вычисление хеша. Отсюда правило: если в коде есть list.Contains(...) внутри цикла, почти всегда нужен HashSet (или ToHashSet() на входе).

Изменяемый элемент — та же ловушка, что с ключом словаря

Элемент множества — это ключ словаря. Значит, правило из главы 9 действует целиком: если GetHashCode зависит от изменяемого поля, после мутации элемент «теряется» — он есть в перечислении, но Contains его не находит.

public sealed record Key { public int Id { get; set; } }   // хеш считается по Id

var set = new HashSet<Key> { new Key { Id = 1 } };
var key = set.First();

key.Id = 2;                                        // хеш изменился

Console.WriteLine(set.Count + " " + set.Contains(key));       // 1 False

Вывод

1 False

Лечится тем же способом: неизменяемый элемент (record с init, позиционный record), суррогатный ключ или удаление до мутации — три варианта разобраны в главе 9, раздел «Как надо: три способа не потерять запись».

Неизменяемое и «замороженное»: ImmutableHashSet и FrozenSet

Если множество заполняется один раз (справочник, набор разрешений, список синонимов), обычный HashSet избыточен: он тратит память на возможность изменения и не защищает от случайной записи. Два варианта на такой случай:

var ids = new[] { 1, 1, 2 };

FrozenSet<int> frozen = ids.ToFrozenSet();                  // System.Collections.Frozen (.NET 8)
ImmutableHashSet<int> immutable = ids.ToImmutableHashSet(); // System.Collections.Immutable

Console.WriteLine(frozen.Count + " (" + frozen.GetType().Name + ") " + immutable.Count);

Вывод

2 (SmallValueTypeComparableFrozenSet`1) 2
  • FrozenSet/FrozenDictionary — создаётся один раз, оптимизирован под чтение: внутри структура, подобранная под содержимое (это видно по имени типа). Изменить нельзя вообще. Лучший выбор для «константы приложения».
  • ImmutableHashSet — «изменение» возвращает новое множество, старое остаётся валидным: ImmutableHashSet<int> next = current.Add(3);. Удобно, когда набор обновляется редко, а читается из разных потоков.
  • Оба безопасны для параллельного чтения и не дают изменить себя случайно — то, чего не хватает HashSet.

Ловушки

  • Результат Add/Remove игнорируют. Именно он отвечает на вопрос «а был ли элемент»: if (!set.Add(id)) { /* уже был */ }.
  • Операции над множествами мутируют получателя. a.UnionWith(b) меняет a; нужен исходный набор — копируйте или берите LINQ.
  • Порядок перебора HashSet не гарантирован и меняется после удалений. Нужен порядок — SortedSet или сортировка при выводе.
  • SortedSet без компаратора требует IComparable<T>, и ошибка появляется не в конструкторе, а при добавлении второго элемента: первый не с чем сравнивать.
var s = new SortedSet<NoCompare>();
s.Add(new NoCompare { Id = 1 });     // ✔ ошибки нет
s.Add(new NoCompare { Id = 2 });     // ✘ нужно сравнение

Вывод

System.ArgumentException: At least one object must implement IComparable.
  • Изменяемый элемент — та же потеря записи, что и с ключом словаря.
  • Компараторы двух множеств должны совпадать по смыслу. new HashSet<string>(StringComparer.OrdinalIgnoreCase) и обычное new HashSet<string> по-разному ответят на IsSubsetOf и SetEquals.
  • list.Contains(...) в цикле — почти всегда нужен HashSet/ToHashSet() (см. замер выше).
★ Что запомнить из главы
  • Add/Remove возвращают bool и не бросают исключений; RemoveWhere — сколько удалил; TryGetValue отдаёт хранимый экземпляр.
  • Операции над множествами — UnionWith (∪), IntersectWith (∩), ExceptWith (∖), SymmetricExceptWith (Δ); все мутируют получателя.
  • Отношения — SetEquals, IsSubsetOf/ IsProperSubsetOf, IsSupersetOf/IsProperSupersetOf, Overlaps; «proper» ложно для равных множеств.
  • Ёмкость — EnsureCapacity, TrimExcess, CopyTo; компаратор задаётся в конструкторе и влияет на всё равенство.
  • Порядка в HashSet нет; сортированный вариант — отдельный тип SortedSet<T>: O(log n), Min/Max, GetViewBetween (живое представление).
  • Поиск: HashSet.Contains ~O(1) против List.Contains O(n) — на замере разница ~300×.
  • Только чтение после старта — FrozenSet; версии — ImmutableHashSet.
