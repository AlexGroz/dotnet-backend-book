Глава 8. Пул потоков и thread pool starvation

Потоки создавать дорого, поэтому .NET их переиспользует. Разберём, как устроен пул и что такое «голодание», которое убивает задержки.

Зачем нужен пул

Если создавать поток под каждый входящий запрос, сервер быстро упрётся в накладные расходы. Поэтому .NET держит пул потоков — набор готовых потоков, которые переиспользуются. По умолчанию потоков примерно по числу ядер.

Две группы потоков в пуле

  • Worker threads — выполняют ваш код и продолжения после await.
  • I/O completion threads — обрабатывают завершение асинхронных операций ввода-вывода.
Ключевая идея

Пока идёт настоящая асинхронная I/O-операция (запрос в БД, HTTP-вызов), поток не занят — об этом позже сообщит операционная система. Один поток обслуживает множество «ожидающих» операций. Это и есть источник высокой пропускной способности.

Thread pool starvation («голодание» пула)

Если внутри потока пула делать блокирующее ожидание (.Result, .Wait(), Thread.Sleep, синхронный вызов БД), поток занят, но ничего не делает. Когда запросов больше, чем потоков, остальные встают в очередь, а новые потоки пул добавляет медленно (примерно по одному за 500 мс). Итог — задержка в секунды при свободном процессоре.

Антипаттерн №1 в серверном коде

// ✘ поток пула застревает в ожидании
var data = GetDataAsync(id).Result;   // или .Wait()

// ✔ блокировки нет — поток освобождается на время I/O
var data2 = await GetDataAsync(id);
Как распознать голодание

Растёт очередь пула и число потоков, а задержка огромная. Ищем блокирующие вызовы. Поднять ThreadPool.SetMinThreads можно лишь как временную меру — это лечение симптома, а не причины.

Вывод: чего нельзя делать

  • Не вызывать .Result и .Wait() на асинхронных операциях.
  • Не спать в потоке пула (Thread.Sleep) — для ожидания есть await Task.Delay.
  • Не держать поток на время долгого ввода-вывода.
★ Что запомнить из главы

Потоки берутся из пула и их нельзя занимать бесполезным ожиданием. Именно поэтому дальше мы перейдём к синхронизации (глава 9), природе ввода-вывода (глава 10) и асинхронности (глава 11).
