Глава 1. Зачем нужен Redis и где он встаёт в .NET-сервисе

Хранилище структур данных в памяти: кэш, счётчики, очереди и блокировки — и границы применимости

подводящая глава

Что такое Redis

Redis — это сервер, который хранит структуры данных в памяти и отдаёт их по сети. Не «база данных с таблицами», а набор типизированных значений по ключу: строка, хеш, список, множество, сортированное множество, поток. Клиент говорит с ним по текстовому протоколу RESP (Redis Serialization Protocol): команда — строка, ответ — типизированное значение.

Три свойства, из которых следует всё остальное:

  • Данные в памяти. Чтение — обращение к RAM, а не к диску; отсюда микросекундные ответы. Плата — объём: память дороже диска, и её надо явно ограничивать (глава 5).
  • Команды выполняются по одной. Пока сервер выполняет команду, следующая ждёт. Поэтому одна команда атомарна: INCR не «потеряет» обновление, а SET … NX не выполнится дважды. Это же свойство — причина, по которой тяжёлая команда над большим ключом тормозит всех клиентов.
  • Персистентность — опция, а не основа. RDB-снимки и AOF-журнал позволяют пережить перезапуск, но Redis — не журнал транзакций СУБД: свежие записи можно потерять (глава 5).
Формулировка

Redis — это общая для всех экземпляров приложения память со структурами данных и атомарными операциями над ними. Кэш — только самый частый способ её применять.

Где он встаёт в .NET-сервисе

Типовая схема: приложение (несколько реплик) → Redis → PostgreSQL. В Redis живёт то, что можно пересоздать или что должно быть общим для реплик, но не требует транзакций СУБД.

Redis удобен именно тем, что все эти задачи решаются одним хранилищем: не нужно поднимать отдельный сервис под счётчики и ещё один под блокировки.

Когда Redis не нужен

Границы применимости
  • Источник истины для денег и заказов. Если потеря секунды записей недопустима — это PostgreSQL, а Redis может быть только ускорителем перед ним.
  • Большие значения. Объект на десятки мегабайт в Redis — это простой сервера на время передачи и удар по сети. Крупные данные — в объектное хранилище или в БД.
  • Полнотекстовый поиск и аналитика. Другой инструмент: PostgreSQL, поисковый движок, колоночное хранилище.
  • Сложные транзакции и отчёты. В Redis есть MULTI/EXEC и скрипты, но это не замена транзакциям СУБД с изоляцией и ограничениями.
  • Замена брокеру сообщений. Списки и потоки Redis умеют очереди, но гарантии доставки, dead-letter, маршрутизация и размножение по подписчикам — это RabbitMQ или Kafka (следующая книга).

Запуск и первая проверка

Для локальной работы достаточно официального образа. Ниже — реальный вывод на Redis 7.4:

docker run --rm -d --name redis7 -p 6379:6379 redis:7-alpine

docker exec redis7 redis-cli ping
# PONG

docker exec redis7 redis-cli info server | grep -E 'redis_version|redis_mode'
# redis_version:7.4.12
# redis_mode:standalone

Порт 6379 — стандартный; PONG означает, что сервер принял соединение и ответил на PING. Дальше можно работать из redis-cli или из кода.

Как с ним говорят из .NET

Уровней два, и путать их не стоит:

  • StackExchange.Redis — «родной» клиент: одно соединение (ConnectionMultiplexer) на процесс, из него берут IDatabase и вызывают команды (StringSetAsync, HashGetAllAsync и т. д.). Даёт доступ ко всем структурам и деталям: TTL, NX, пайплайны.
  • IDistributedCache — абстракция .NET поверх любого распределённого кэша (AddStackExchangeRedisCache): только «положить/взять байты по ключу с временем жизни». Удобно, когда кэш нужен именно как кэш, а не как структура данных.

Обе линии разбираются дальше: подключение и команды — глава 2, структуры данных — глава 3, кэширование как паттерн — глава 4, память и эксплуатация — глава 5.

★ Что запомнить из главы
  • Redis — хранилище структур данных в памяти, а не «кэш» и не «быстрая БД»: строки, хеши, списки, множества, сортированные множества, потоки.
  • Одна команда атомарна, потому что сервер выполняет команды по одной; тяжёлая команда над большим ключом тормозит всех.
  • Жизнь без Redis должна быть возможна: всё, что в нём лежит, либо пересоздаётся, либо дублирует PostgreSQL.
  • Из .NET — два уровня: StackExchange.Redis для структур и IDistributedCache для простого кэша.
