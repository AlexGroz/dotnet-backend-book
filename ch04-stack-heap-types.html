Глава 4. Стек, куча и типы: где живут данные

Чтобы понять сборку мусора и стоимость аллокаций, сначала нужно увидеть, где в программе вообще лежат данные.

Две области памяти

  • Стек — быстрая область для локальных переменных и вызовов методов. Растёт и сжимается автоматически, освобождается при выходе из метода.
  • Куча — область, где живут объекты. Объект живёт в куче до тех пор, пока на него есть ссылки; очисткой занимается сборщик мусора (глава 6).

Что такое «аллокация»

Аллокация — это выделение памяти под новый объект. Когда вы пишете new или создаёте строку, рантайм находит свободное место в куче и отдаёт его объекту. Именно этот шаг и называется аллокацией.

var user = new User();       // аллокация: в куче выделено место под объект
var name = "Алексей";        // строка — ссылочный тип: объект в куче, в переменной — ссылка
var list = new List<int>();  // и здесь
Строка — не «в стеке»

Частое заблуждение: «string лежит в стеке, поэтому он быстрее». На самом деле string — ссылочный тип: объект живёт в куче, а в переменной на стеке лежит только ссылка на него. Дополнительно строковые литералы интернируются: два одинаковых литерала — один объект, и при обращении к литералу новой аллокации не происходит.

А StringBuilder быстрее не из-за стека, а потому что меняет свой буфер: конкатенация в цикле — это O(n²) копирований, StringBuilder — O(n). Подробный разбор — «C#: язык и типы», глава 2.

Сама аллокация выполняется мгновенно, но у неё есть отложенная цена: каждый созданный объект потом придётся «убрать» сборщику мусора (глава 6). Чем больше объектов в секунду — тем больше работы у GC, тем больше процессорного времени уходит не на полезную работу.

Ключевая связь для всей части II

Аллокация → мусор → работа GC → расход процессора. Поэтому «не создавать лишних объектов» — это не микрооптимизация, а способ не грузить CPU.

Отсюда же практический приём: значимые типы (struct) часто создаются без аллокации — но не всегда. Место зависит не от типа, а от того, где живёт значение:

  • локальная переменная или параметр → стек, без аллокации;
  • поле класса → внутри объекта в куче (аллокация была при создании объекта);
  • элемент массива или List<T> → в массиве в куче;
  • упаковано в object → новая аллокация в куче;
  • захвачено лямбдой или пережило await → в объекте-замыкании / состоянии в куче.

Поэтому «struct всегда в стеке» — неверное упрощение; подробный разбор — «C#: язык и типы», глава 3.

Ссылочные и значимые типы

Частый вопрос: при чём тут int и зачем вообще struct?

Прямой ответ. В строке int j = 25; тип int — это уже значимый тип (по сути, «встроенный struct»). Объявлять ничего не нужно: он готов из коробки.

struct — это не альтернатива int, а способ создать свой тип-значение. Поэтому вопрос «когда struct, а когда просто int» правильнее поставить так:

Что нужноЧто брать
Просто число, символ или датаint, double, bool, DateTime — они уже значимые
Своё маленькое «значение» из 2–4 полей (точка, диапазон, сумма)свой struct
Сущность с поведением (пользователь, заказ, сервис)class

Пример: свой значимый тип — точка

public readonly struct Point          // свой значимый тип
{
    public int X { get; }
    public int Y { get; }

    public Point(int x, int y) { X = x; Y = y; }
}

// Пользуемся так же обыкновенно, как int: это значение, а не объект в куче
var p = new Point(3, 5);
var q = p;                 // копия значения: q.X = 3, q.Y = 5
Console.WriteLine(p.X);    // 3
«new» у struct не создаёт объект в куче

Запись new Point(3, 5) выглядит как создание объекта, но для struct аллокации в куче нет: создаётся значение. В этом и выгода — маленькие типы-значения дёшевы, их можно создавать часто и не нагружать сборщик мусора.

Ссылочный тип (class)Значимый тип (struct)
Где живётВ куче, а переменная хранит ссылку на негоЗначение — «прямо в переменной»
ПрисваиваниеКопируется ссылка (тот же объект)Копируется всё значение
Может быть nullДаНет (кроме Nullable<T> / int?)
СтоимостьАллокация в кучеОбычно без аллокации (если значение на стеке)

Разница наглядно

class PointClass { public int X; }    // ссылочный
struct PointStruct { public int X; }  // значимый

var a = new PointClass { X = 1 };
var b = a;        // b ссылается на ТОТ ЖЕ объект
b.X = 99;         // a.X тоже станет 99

var c = new PointStruct { X = 1 };
var d = c;        // d — независимая копия
d.X = 99;         // c.X останется 1
Когда брать struct, а когда class

По умолчанию берите class. struct оправдан, когда тип одновременно:

  • маленький — обычно 2–4 поля, немного байт;
  • неизменяемый по смыслу — «значение», а не «сущность»;
  • создаётся очень часто — тогда экономия на аллокациях заметна.

Примеры struct: точка, диапазон дат, сумма в копейках, ключ для словаря. Примеры class: пользователь, заказ, сервис — всё, что является «объектом с поведением».

Почему это важно для нагрузки

Ссылочный тип — это объект в куче, то есть работа для GC. Значимый тип обычно дешевле. Но если значимый тип «упаковать» в объект, преимущество теряется — об этом дальше.

Ссылка и «null»

Переменная ссылочного типа хранит адрес объекта. Несколько переменных могут указывать на один объект — поэтому изменение через одну видно через другую. Если ссылка нулевая (null), объекта нет.

Первое знакомство с упаковкой (boxing)

Иногда значимый тип нужно воспринять как object. Тогда рантайм выделяет объект в куче и копирует туда значение — это и есть упаковка (boxing). Обратная операция — распаковка (unboxing).

int n = 42;
object boxed = n;       // упаковка
int back = (int)boxed;  // распаковка

Значение при упаковке «уезжает» в кучу и возвращается оттуда. Пошагово это выглядит так:

Строка кодаЧто при этом со стеком и кучей
int n = 42; Значение 42 лежит на стеке (в переменной n). Кучи не касается — аллокации нет.
object boxed = n; В куче создаётся новый объект (аллокация), и в него копируется 42. Переменная boxed (на стеке) хранит ссылку на этот объект. При этом исходный n на стеке остаётся как был.
int back = (int)boxed; Из объекта в куче значение копируется в новую переменную back на стеке. 
Стек                     Куча
┌──────────────┐
│ n     = 42   │  ──(копия значения)──►  ┌───────────────────────┐
├──────────────┤                         │ объект: { значение 42 }│  ← аллокация
│ boxed ───────┼───(ссылка)────────────► └───────────────────────┘
├──────────────┤
│ back  = 42   │  ◄──(копия значения)─────┘
└──────────────┘
Объект в куче останется мусором, пока его не уберёт сборщик (глава 6).
Три следствия, которые важно запомнить
  • Это аллокация — появился объект, который потом создаст работу для GC.
  • Это копия. Если позже изменить n, boxed не изменится (и наоборот).
  • Упаковка бывает незаметной. Например, при добавлении int в не-generic коллекцию — глава 7.
★ Что запомнить из главы

Локальные переменные и вызовы — на стеке; объекты — в куче. Путь к пониманию памяти: ссылочные типы живут в куче (работа для GC), значимые — дешевле, но могут «упаковываться» в объект.
