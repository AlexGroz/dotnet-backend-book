Глава 3. Как .NET исполняет код: CLR, IL, JIT

От исходника на C# до машинных инструкций. Без этой картины непонятно, почему код «прогревается» и откуда берётся стоимость объектов.

Путь кода: C# → IL → машинный код

  1. Компилятор C# (Roslyn) переводит исходник не в машинный код, а в промежуточный язык IL и метаданные. Итог — сборка .dll.
  2. CLR (Common Language Runtime) загружает сборку и во время выполнения JIT-компилирует методы из IL в машинный код того процессора, на котором запущено приложение.
  3. Дальше метод исполняется уже как «родной» машинный код.
Следствие, важное для практики

Раз метод компилируется во время выполнения, у кода есть прогрев: первые вызовы медленнее. Поэтому микробенчмарки всегда делают с разогревом (глава 20), а «первый запрос после старта» может быть медленнее последующих.

Tiered compilation: быстро стартовать, быстро работать

.NET использует многоуровневую компиляцию: сначала метод компилируется «быстро и просто», чтобы приложение стартовало без задержек. Если метод оказался горячим — его пересоздают уже с полными оптимизациями. Так приложение быстро запускается и быстро работает под нагрузкой.

Что такое «горячий путь» (hot path)

Это код, который выполняется очень часто — например, обработка каждого запроса. Именно на нём важны все оптимизации из этой книги. Единичный, редко вызываемый код оптимизировать не нужно — выигрыш незаметен, а читаемость падает.

AOT и ReadyToRun — кратко

  • ReadyToRun — часть кода скомпилирована заранее, чтобы сократить старт.
  • Native AOT — сборка сразу в машинный код, без JIT. Полезно для CLI и функций, где важен мгновенный старт.

Для обычного сервера под нагрузкой это чаще деталь, а не необходимость: горячий код всё равно получит полные оптимизации через tiered compilation.

★ Что запомнить из главы

Код компилируется в IL и JIT-компилируется во время выполнения, поэтому есть «прогрев». Оптимизировать стоит только горячие пути. Как устроена память и почему объекты стоят денег — в следующей главе.
