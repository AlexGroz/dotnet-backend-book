Глава 6. Типы данных и их особенности

Тип данных — это не формальность: он определяет, как значения сравниваются, индексируются и сколько занимают. А при миграции из Oracle неверный тип приводит к «тихим» багам.

Числа

ТипДля чегоНюанс
smallint / int / bigintЦелые числа (2 / 4 / 8 байт)Берите с запасом: int хватает не всегда
numericТочные числа — деньги, бухгалтерияБез ошибок округления, но медленнее целых
real / double precisionПриближённые (научные) вычисленияНе для денег: накопятся копеечные расхождения
Правило для денег

Только numeric (или целое число в минимальных единицах, например копейках). float для денег — классическая ошибка.

Первичные ключи: GENERATED ... AS IDENTITY (современный способ) или serial/bigserial (старый, но распространённый).

Строки

  • text и varchar(n) — в PostgreSQL работают одинаково быстро; разница только в ограничении длины.
  • varchar(n) — если длину действительно нужно ограничивать;
  • char(n) — не используйте: он дополняет строку пробелами до длины n, что даёт странные сравнения.

Дата и время

ТипЧто хранитКогда брать
dateТолько датуКогда время не нужно
timestampДату и время без часового поясаРедко — легко перепутать зоны
timestamptzМомент времени с учётом зоныОбычный выбор для «когда это произошло»
Ловушка из мира Oracle

В Oracle тип DATE хранит и дату, и время. Если при миграции слепо сопоставить его с PostgreSQL-date, время потеряется. Правильный маппинг — timestamp / timestamptz (глава 28).

Логический тип

boolean — true / false / NULL. Не заменяйте его «флажками» в виде чисел или символов — читаемость и индексы лучше с настоящим boolean.

NULL — самый коварный «тип»

NULL — это «значение неизвестно», а не «0» и не «пустая строка». Отсюда два сюрприза:

  • Любое сравнение с NULL даёт NULL (то есть «неизвестно»), а не false. Поэтому проверяют только так: WHERE col IS NULL / IS NOT NULL.
  • В WHERE строка с NULL в условии не пройдёт — её как будто нет. Это часто «теряет» данные в отчётах.
-- ✘ так ничего не найдётся, даже если в колонке NULL
SELECT * FROM orders WHERE comment = NULL;

-- ✔ правильно
SELECT * FROM orders WHERE comment IS NULL;

NULL и уникальность

В PostgreSQL NULL-ы в уникальном индексе считаются разными, поэтому в колонку с UNIQUE можно вставить много NULL (поведение можно изменить через NULLS NOT DISTINCT, PG15+).

Пустая строка ≠ NULL

В PostgreSQL '' — это обычная пустая строка, а не NULL (в Oracle наоборот). Поэтому ограничение NOT NULL пустую строку пропустит. Это важно при миграции (глава 27).

Прочие типы (кратко)

  • jsonb — для гибких структур; индексируется через GIN (глава 10);
  • uuid — идентификаторы без «порядка» и без утечки количества записей;
  • массивы и enum — есть, но применяйте осознанно.
★ Что запомнить

Выбирайте тип по смыслу: деньги — numeric, время — timestamptz, строки — text/varchar. Помните, что NULL — это «неизвестно»: сравнения с ним требуют IS NULL, а '' — не NULL. При миграции из Oracle тип DATE содержит время.
